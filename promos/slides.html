The preview is
what runs

A plan lists specific records with a decided action each, and pressing the button runs that list — it never searches again. Rows created between the preview and the button would otherwise be deleted without anyone having seen them. The plan is fingerprinted, and a mismatch stops the run.

Anonymise is not a softer erase

A completed order is a tax record — six years in the UK, ten in Germany. But the order is what the obligation covers, not the customer's name inside it. So Lock empties the order and keeps it.

What stays

Because a VAT return is built from it

  • The money, the tax, the line items
  • The date the order was placed
  • Country and region, and nothing finer

What goes

Because none of it is the obligation

  • Name, email, phone, street address
  • The link back to the user account
  • Replaced by a pseudonym derived from the address — and in a bulk sweep, one each, because ten thousand orders sharing a pseudonym are linkable again

Retention is erasure with a
different way of choosing records

Not "everything belonging to this person" but "everything in this scope older than this date" — and from there it is the same plan, the same preview, the same executor, the same ledger.

01stale()The collector picks the records the rule has aged out
02planFor()The same plan builder an erasure uses
03previewSpecific records, a decided action each
04fingerprintPosted back, and a mismatch throws
05run()Walks the list, and never re-searches
06ledgerAppend-only, with no update or delete path
